# 采集字段、深度分析与报告结构（阶段 3 用）

## 一、每款游戏基础信息（8 项）

1. 游戏名称（中英文 + 开发商/发行商）
2. 上架平台与具体上架日期（分平台标注；精确日期缺失写「待核实」）
3. 游戏类型标签（主玩法 + 子品类，如「三消 + 模拟经营」「物理弹射 · Roguelike」）
4. 当前排名与最高排名（分平台标注，如「GP 美区免费 #1 · iOS 美区免费 #3」）
5. 预估下载量（区间口径，如「GP 累计约 370 万（AppBrain 口径，估算）」）
6. 预估收入（区间，区分 IAP / IAA / 买断；无公开数据写「无公开数据，估算区间待核实」）
7. 用户评分与评论数（分平台，标注快照日期）
8. 游戏简介（官方描述 2 句话概括）

变现模式标签（单独字段）：IAP / IAA / 混合变现 / 买断制 / 订阅。

## 二、深度分析 8 节（每款必出）

1. **一句话定位**：给什么人、在什么场景下玩什么的游戏。
2. **玩法亮点**：核心循环（单局 30 秒-3 分钟在做什么）+ 元循环（局外养成/解锁什么）。
3. **核心卖点**：商店页前三张截图、预告片、关键词宣传主打什么。
4. **资源循环方式**：货币体系、体力/能量系统、成长线如何驱动留存与付费。
5. **变现设计**：广告点位（激励视频/插屏位置）、内购档位、付费墙位置。
6. **用户口碑洞察**：5-8 条中文好评关键词 + 3-5 条差评关键词（实际抓取），说明真实爽点与痛点。
7. **独立开发者借鉴建议**：2-3 条具体可执行建议（如「借鉴其三消关卡的物理碰撞表现，换成自有 IP 角色」「其开局 60 秒引导节奏值得复用，但中期数值曲线太肝需压缩 40%」）。
8. **注意事项**：版权风险、玩法专利、市场饱和信号、版号风险、需避开的坑。

## 三、报告结构（按序输出）

1. **本周榜单速览表**：按综合分从高到低，列：排名 / 游戏名 / 平台 / 类型 / 综合分 / IAA 潜力分 / 一句话定位。
2. **每款游戏一张卡片**：基础信息 + 12 维打分（表格/条形图）+ 深度分析完整展开。
3. **本周灵感总结**：
   - 共性题材/玩法趋势（至少 3 条）；
   - 最适合 1-3 人小团队切入的 2-3 个方向（给样板游戏 + 为什么 + 成本量级）；
   - 「看起来火但千万别碰」的坑（写明原因）。
4. **观察项清单**：未进主榜候选 + 具体原因。
5. **数据口径声明**：时间窗口、环比「待核实」说明、下载/收入估算口径、评分评论快照时间、打分主观性声明、核验情况（哪些数字经 API 实测）。

## 四、数据口径与标注规范

- 每个数字注明来源与口径；不确定写「待核实」，禁止编造。
- 下载量估算：GP 按 AppBrain 安装量与榜单位置推算；Steam 按评论数 ×30-60 系数（付费买断惯例），均未扣平台分成，标注估算。
- 引用：工具/API 返回的 URL 原样保留；报告与看板内附来源 URL 列表。
- 评分与评论数注明快照日期（如 2026-10-09 快照）。
